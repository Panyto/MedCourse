# 谁能改什么（g6_core v0.1）

| 内容 | 谁写 | 伙计能不能改 |
|---|---|---|
| `q6_kit/entities.py`（实体尺子 g6-rules-0.1，词表和开放后缀） | 总经理 | 不能改。觉得要改，写规则提案：哪一类、哪个词或后缀、多少份病历受影响（只给计数和位置，真实一侧只给满足守则 1.2 的短串），建议怎么改。总经理批准后升版本 |
| `q6_kit/care_quota.py`（LLM-CARe 语料层移植） | 总经理（照抄公开代码，改动只有 README 2.1 的 A1–A4） | 不能改。原代码的算式问题（README 2.2）**照原样用**，不许"顺手修好" |
| `q6_kit/official/`（公开代码原件、示例参考文件） | 原样 | 不能改，自检核对 sha256 |
| `q6_kit/kcov.py`、`diversity.py`、`tail.py`、`b6.py`、`split.py`、`mask.py` | 总经理 | 不能改；种子、门槛、份数不调 |
| `ruler_g3/`、`ruler_g4/`、`q45_kit/` | 总经理（g45_core 0.2 原样） | 不能改 |
| `tests/` | 总经理 | 不能改；可以另加自己的测试文件 |
| 读真实病历建 7 字段和实体集合（内存）、语料层的 Adviser 和 Reviser 调用（复用关1 G1-D v1.5 的模板、解析和 8B 请求）、长尾初稿生成（复用关1 G1-B 生成 CARe-S1 的脚本）、批跑、断点续跑、建表、打码导出、标注页面、完整样例、打包 | 伙计 | 伙计自己写，放 `code/`，进包 |

发现代码有错（崩溃、明显写错）时：不要就地改。把出错的位置（文件、行号、槽位号或住院号、字段、字符偏移）和报错类型写进 GAPS；能绕开的先绕开（跳过该病历并计数），绕不开就停下这一步，先做别的。
