## 几条硬规矩，代码里已写死

- 模型服务只能是 `127.0.0.1`（守则 P1），别的地址直接报错。
- 每次请求都写明 temperature、top_p、top_k、min_p、repetition_penalty、max_tokens、seed，对话接口关闭思考模式；少给任何一项直接报错。抽取用 `EXTRACT`（0、1.0、-1，同 G1-D、G1-E 评测），写手三臂都用 `WRITE`（0.7、0.8、20，同 G1-B 生成），min_p 0、repetition_penalty 1.0。
- 抽取真实文书的产物只能写到 `/home/weify/pyt/product/derived/` 下（P2），合成行要加 `--synthetic`。
- schema 不用 `maxLength`。
- 输出和日志只有计数和位置，异常不带 message。
- L3、L4 不读真实文本，只读 `Stats`。
- `synth_export` 只收自由模式、非 LoRA 写手的文书，每次不超过 20 份，输出目录不能在 `derived/`、`data/` 下。

## 按章节抽（采纳监督员的建议，有两处改动）

| 点 | 做法 |
|---|---|
| 切片 | 入院、出院、首程按 `split_sections` 切；病程去抬头后整篇一片；超过 600 字按句再切 |
| 防截断 | 不靠"章节一定短"。事件顶到 40 或输出被截断时，对半重抽，最多两层；切不开的标 `truncated` 并计数 |
| 粒度 | 切片的位置和章节名进 `EventRecord`，S3 直接配成"计划 → 真实段落" |
| 吞吐 | 不假设更快：切片多了调用数也多，去掉 20 条上限后总输出会增加。`counts.json` 用实测 token 和份/小时说话 |

切片长度的真实分布由 `seg_diag` 量，不预设 100–400 字。

## 已知的取舍

- `stats.py` 是规则读数，S2 的抽取产物出来后换掉，字段不变。
- 影像结论是一句定性描述，没有数值：v0 没有影像的统计，写手只写定性结果。
- `TemplateWriter` 的字数和文风没有参考价值，只说明流程和闸门通了。
- 拷贝是整句原样拷贝，`numeric_changed` 靠每天同一句式的体征实现；`near` 留给 S3。
- 配对模式只把槽位的属性、住院天数、手术日当条件，日程不借真实骨架。
